# Secret mounts per sandbox service (names only, never values)

One file per Cloud Run service or job. Each line is `ENV_NAME=SECRET_NAME`; the deploy mounts
`ENV_NAME` from `SECRET_NAME:latest` in project pivota-sandbox. These files are the single source
of truth for three things:

1. what `deploy_sandbox.sh` mounts (`--set-secrets`) for the four services. `ops.list` is the
   exception: no service runs as `sa-sandbox-ops`; it only grants the two one-off jobs (RUNBOOK
   steps 10b and 14) their secrets. Step 14's script reads `PIVOTA_API_KEY` in-process;
2. which service account `bootstrap_sandbox.sh iam` grants `secretAccessor` on which secret
   (per secret, never project-wide);
3. the allowlist `verify_sandbox.sh` compares the project's secrets against. A secret in the
   project that no file here names is a failure.

Every secret is one of three kinds (`bootstrap_sandbox.sh secrets` labels each with `origin=`):

| origin | secrets | how the value is made |
|---|---|---|
| `sandbox-cloudsql` | `pivota-db-password`, `DATABASE_URL`, `DATABASE_URL_NOVERIFY`, `SCHEMA_APPLY_DATABASE_URL`, `SCHEMA_APPLY_ROLE_VERIFIER` | generated by the bootstrap for the sandbox's own Cloud SQL (the last two: the schema-apply role's DSN, and the SCRAM verifier of the same password, minted together; RUNBOOK 10a-sandbox) |
| `reap-sandbox` | `REAP_API_KEY` | created EMPTY; the owner adds the version from Reap's sandbox dashboard (runbook step 4) |
| `minted-in-sandbox` | every other name | random, generated inside pivota-sandbox by the bootstrap; never existed in staging or prod. `PIVOTA_API_KEY` (the gateway's service key) is minted as `ak_test_<64 hex>`, the format the gateway's sandbox boot check and MCP loopback require. `ISSUING_AGENT_ASSERTION_SECRET` (review S9) is the HMAC key the gateway signs the verified partner with and web checks; it is mounted by exactly those two (`check_profile.py` R8), so partner credit works in the sandbox |

No value is ever copied from pivota-staging or pivota-prod. `check_profile.py` refuses a list
that names a secret outside `ALLOWED_SECRETS` in that file.
