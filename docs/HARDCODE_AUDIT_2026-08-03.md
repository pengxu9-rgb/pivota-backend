### [1.1] +200 pdp_scope bonus exceeds the entire candidate_score scale (cap 1.4 == 140 raw points), so every canonical row pins at max relevance

- **Location:** `services/pivot_query_service.py:1048`
- **Category:** proxy-for-signal · **Confidence:** high
- **Literal:** `CASE WHEN p.pdp_scope = 'multi_merchant_canonical' THEN 200 ELSE 0 END  (normalized at :765 by max(0.12, min(score/100.0, 1.4)))`
- **Should read from:** relevance must be computed from the text terms; the scope label belongs in a separate structural key (the text_score/structure_score split at :1086/:1094 already exists but is gated behind RECALL_RELEVANCE_V2, which is default OFF at :1276)
- **Failure mode:** rank_score contains NO partial/substring text terms at all — the only text terms are the six EXACT equality terms (120/110/105/100/90/80). For the entire non-exact population (the 'catalog_discovery' lane) the score is decided purely by pdp_scope(200) + lifecycle(60/20) + category(90). Ran it: a merchant_owned published row whose TITLE contains the whole query scores 60 -> candidate_score 0.6; a multi_merchant_canonical published row that matches only on a brand substring scores 260 -> candidate_score 1.4. Worse, the /100 normalisation caps at 1.4 == 140 raw points while the scope bonus alone is 200, so rank_score 200, 260, 350 and 590 ALL normalise to exactly 1.4 — every canonical row is indistinguishable from every other and from a perfect match. Per MEMORY, 78% of rows carrying this label have exactly one seller (stamped unconditionally by DEFAULT_PDP_SCOPE at services/catalog_enrichment_agent/ingestion.py:68), so the dominating term is being read off a literal, not a signal.
- **Evidence:** PYTHONPATH=<repo> .venv/bin/python scratchpad/demo.py -> section A: rank_score=60 -> candidate_score=0.6 (merchant_owned, exact-phrase title) vs rank_score=260 -> candidate_score=1.4 (canonical, brand substring only).
